# clangd 설정

Garage는 빌드 생성기를 강제하지 않고 현재 CMake 구성에서 clangd용 컴파일 정보를 생성합니다.
Python, Ninja 또는 특정 IDE 확장은 이 기능의 필수 의존성이 아닙니다.

## 사용 순서

1. 사용할 CMake 구성 프리셋을 선택하고 Configure를 실행합니다.
2. 해당 구성의 `garage-clangd` 타깃을 실행합니다. 이 타깃은 C++ 소스를 컴파일하지 않습니다.
3. IDE의 clangd 언어 서버를 다시 시작합니다.

`Garage` 타깃을 빌드하면 `garage-clangd`도 선행 실행되므로 별도로 실행할 필요가 없습니다.
프리셋 또는 Debug/Release 구성을 바꾼 후에도 같은 절차를 사용합니다. 옵션 파일을 직접 수정하지 않습니다.
Configure만 실행한 단계에서는 컴파일 데이터베이스가 아직 갱신되지 않습니다.

## 생성 방식

- CMake가 네이티브 컴파일 데이터베이스를 생성하는 단일 구성 생성기에서는 해당 결과를 사용합니다.
- Visual Studio 등에서는 CMake File API의 선택한 구성과 `Garage` 타깃 정보를 변환합니다.
- 소스별 컴파일 그룹의 옵션, 전처리기 정의, include 경로 및 C++ 컴파일러를 기록합니다.
- 생성된 소스와 외부 라이브러리 자체의 번역 단위는 File API 변환 대상에서 제외합니다.
- 결과는 저장소 루트의 `compile_commands.json`에 생성되며 Git에 포함하지 않습니다.
- `.clangd`에서는 분석 시에만 PCH 강제 포함 옵션을 제거합니다. 실제 빌드의 PCH 설정은 유지합니다.

루트 데이터베이스는 마지막으로 `garage-clangd`를 실행한 빌드 폴더와 구성을 나타냅니다.
여러 구성을 동시에 사용할 경우 각각의 빌드 폴더를 대상으로 별도 clangd 연결 구성이 필요합니다.

File API 결과는 실제 빌드 명령 전체를 그대로 기록한 파일이 아닙니다. 변환 방식은 현재 프로젝트의
일반 C++ 번역 단위를 대상으로 하며, 향후 사용자 정의 컴파일 규칙이나 C++ 모듈을 추가하면 확장이 필요합니다.
다른 플랫폼을 분석하려면 해당 플랫폼의 컴파일러와 SDK가 필요합니다.
